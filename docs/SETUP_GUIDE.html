Get Agentic SOC running on your laptop

About 20 minutes, no prior experience and no special hardware. You install two free programs, run one command, and answer a few questions. Tick each step off as you go.

    Install Python

    The backend (the AI agents and the API) is written in Python. Version 3.12 is the safest choice.

    1. Download Python 3.12 from python.org/downloads/windows (“Windows installer (64-bit)”).
    2. Run it. On the first screen, tick Add python.exe to PATH, then click Install Now.
    3. Open PowerShell (press the Windows key, type “PowerShell”, press Enter) and check it worked:
    py --version
    1. Download Python 3.12 from python.org/downloads/macos and open the .pkg file.
    2. Click through the installer, then open Terminal (Cmd + Space, type “Terminal”) and check:
    python3 --version

python3 --version

    You should see Python 3.12.x (3.10 to 3.13 also work).

    3

    Get a free Llama 3 key optional

    The triage agent thinks with Meta’s open-weight Llama 3. You don’t have a GPU, so the easiest option runs it on someone else’s servers for free. You can skip this: the agents then use a built-in rule-based analyst, and you can add a key later.

    1. Go to openrouter.ai/settings/keys and sign in with Google or GitHub.
    2. Click Create Key, give it a name like “agentic-soc”, and copy the key (it starts with sk-or-).
    3. Keep it somewhere safe for a few minutes. The setup script will ask for it.

    Free models have rate limits. If the model is busy, that alert is triaged by the rule-based analyst instead, and you’ll see a note in its reasoning trace. Nothing breaks.

    Prefer to run Llama on your own laptop?

    Install Ollama, then choose “Ollama on this laptop” during setup. It downloads Llama 3.2 3B (about 2 GB) and runs on your CPU. It’s slower, around 10–40 seconds per alert, but nothing leaves your machine.

    What about Groq?

    Groq is supported and very fast, but it retired its Llama 3 models in August 2026. If you pick Groq, the default model is the open-weight openai/gpt-oss-20b.

    Try the dashboard

    Sign in with your username and password, then follow one alert all the way through.

    Alert arrives→Supervisor picks a playbook→Threat intel searches the RAG store→Llama 3 gives a verdict→Response agent proposes a fix→You approve→SOAR applies it
    1. Press Simulate alert (top right). The case opens and the reasoning trace fills in live, one agent rail at a time.
    2. When it finishes, read the verdict, then press Approve on a proposed change and confirm. The trace shows your decision and the result.
    3. Open Blocklist & audit to see the blocked address and press Undo to roll it back.
    4. Open Threat intel and search for “many failed ssh logins”. That’s the same RAG search the agents run.
    5. The API explorer is at localhost:8000/docs.

    To stop everything, press Ctrl + C in the terminal. To start again later:

    py setup_soc.py --start

    Send your own alerts optional

    Any tool that can call a webhook (Wazuh, Suricata, Splunk, a cron script) can send alerts. Use the INGEST_API_KEY value from your .env file.

    $key = "PASTE_INGEST_API_KEY"
Invoke-RestMethod -Method Post -Uri http://localhost:8000/api/alerts `
  -Headers @{ "X-API-Key" = $key } -ContentType "application/json" `
  -Body '{"title":"Brute force on VPN","src_ip":"203.0.113.10","username":"alice","severity":"high","category":"authentication","description":"120 failed logins in 3 minutes","raw":{"failed_attempts":120}}'
    curl -X POST http://localhost:8000/api/alerts \
  -H "X-API-Key: PASTE_INGEST_API_KEY" -H "Content-Type: application/json" \
  -d '{"title":"Brute force on VPN","src_ip":"203.0.113.10","username":"alice","severity":"high","category":"authentication","description":"120 failed logins in 3 minutes","raw":{"failed_attempts":120}}'
    curl -X POST http://localhost:8000/api/alerts \
  -H "X-API-Key: PASTE_INGEST_API_KEY" -H "Content-Type: application/json" \
  -d '{"title":"Brute force on VPN","src_ip":"203.0.113.10","username":"alice","severity":"high","category":"authentication","description":"120 failed logins in 3 minutes","raw":{"failed_attempts":120}}'

    The address 203.0.113.10 is reserved for documentation, so the response agent’s guardrails refuse to block it and say so in the trace. That’s the safety net working. Real attacker addresses get a proposed block for you to approve.

    To give the agents more context, import your own intel (a team blocklist, notes from past incidents) as CSV or JSON in Threat intel → Add your own intel, or drop files into backend/data/intel_import/.

    Publish to GitHub and Docker Hub optional

    One command creates your GitHub repository, pushes the code, and stores your Docker Hub token as an Actions secret. From then on, every push runs the tests and builds container images automatically.

    1. Install Git if you don’t have it.
    2. Create a GitHub token at github.com/settings/tokens/new with the repo and workflow boxes ticked.
    3. Create a Docker Hub account and an access token at app.docker.com → Personal access tokens (Read & Write).
    4. Run:
    py setup_soc.py --github
    python3 setup_soc.py --github
    python3 setup_soc.py --github

    Then watch the build at github.com/YOUR_NAME/agentic-soc/actions. Your images appear as YOUR_DOCKERHUB_NAME/agentic-soc-backend and …-frontend.

    Your .env file with passwords and keys is listed in .gitignore, so it is never pushed.

    If something goes wrong

    Run the doctor first. It lists what’s installed, what’s missing and what’s running.

    py setup_soc.py --doctor
    python3 setup_soc.py --doctor
    python3 setup_soc.py --doctor
    “python3” opens the Microsoft Store

    Use py instead, for example py setup_soc.py. You can also turn off the Store shortcut in Settings → Apps → Advanced app settings → App execution aliases.

    “node” or “npm” is not recognised

    Close every terminal window and open a new one; it only picks up newly installed programs when it starts. If it still fails, reinstall Node.js LTS and restart the computer.

    A package fails to install with pip

    This usually means a very new Python (3.14) without ready-made packages yet. Install Python 3.12, delete the backend/.venv folder, and run the setup again.

    “Address already in use” or the backend didn’t start

    Another program is using port 8000 or 3000, often an earlier copy of this project. Close old terminal windows (or restart), then run --start again. The last lines of logs/backend.log say exactly what failed.

    The status bar says the model isn’t reachable

    Check the key with --configure. For Ollama, make sure the Ollama app is running and you pulled the model with ollama pull llama3.2:3b. Alerts are still triaged by the rule-based analyst in the meantime.

    I forgot my dashboard password

    Open the .env file in the project folder with any text editor; it’s on the ANALYST_PASSWORD= line. Or set a new one with --configure.

    Does it use Milvus on Windows?

    Milvus Lite (the embedded version) only runs on macOS and Linux, so on Windows the RAG store uses a built-in vector index with the same behaviour. To use a full Milvus server anywhere, run docker compose --profile milvus up and set MILVUS_URI=http://localhost:19530 in .env.
